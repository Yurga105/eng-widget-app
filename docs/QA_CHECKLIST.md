# QA-чек-лист — ручная приёмка (этапы 8–12, PLAN.md §8)

> Ручная матрица проверки на устройстве. Базовое устройство: **RMX2001 / Android 11 (SDK 30) / ColorOS**.
> Автопричитка: `flutter analyze` — чисто, `flutter test` — 56/56 на этапе 8, 69/69 после этапов 9–10 (этап 10 перевёл ожидания на en — локаль тестового окружения, количество тестов сохранено), 76/76 после этапа 11 (+7 — адаптивный UI), 91/91 после этапа 12 (+15 — фото-ассоциации); релизный APK собирается, ноль сетевых прав.
> Помечено ☐ — за пользователем; ☑ — проверено автоматикой/в процессе сборки.

## 1. Иконки и превью (новое в этапе 8)

- ☐ Иконка приложения на домашнем экране ColorOS — зелёная «W.» с янтарной точкой (после редизайна этапа 10; на API 30 действует адаптивная `mipmap-anydpi-v26`, PNG-ряд 48–192 px перегенерирован из того же дизайна; для API<26 принимается по факту сборки — визуально на этом устройстве не виден).
- ☐ Пикер виджетов: долгий тап по рабочему столу → «Виджеты» → «Слово дня» — превью-карточка (`previewImage`, PNG 480×220) с записью «accomplish» / достигать, выполнять.
- ☑ Файл `widget_preview.png` — строки влезают, IPA `/əˈkɑːmplɪʃ/`, перевод капсом (проверено при генерации).
- ☐ Уведомление в шторке: маленькая иконка — белая «W.» (alpha-only `ic_stat_word`; точка заливается цветом системы — норма).

## 2. Виджет — базовый цикл

- ☐ Добавление виджета 4×2 из пикера → сразу карточка слова дня (или плейсхолдер «Откройте приложение», если база ещё не синкилась — риск §9-7; после первого запуска приложения — слово).
- ☐ Тап по виджету → карточка той же даты + янтарная метка «из виджета».
- ☐ Открытие приложения → виджет перерисовывается (синк на старте).

## 3. Смена слова

- ☐ После полуночи слово в виджете меняется само ≤30 мин (`updatePeriodMillis`; принять окно §9-2).
- ☐ Ребут устройства → виджет сразу показывает слово новой даты (`BootCompletedReceiver`), уведомление на 09:00 не пропало (восстановление ресивером плагина).
- ☐ Полночь при живом процессе → слово меняется полуночным таймером приложения.

## 4. Темы

- ☐ Системная светлая → виджет в светлой палитре; тёмная → виджет в тёмно-зелёной ночной (без перезапуска). Приложение всегда светлое (этап 10: `ThemeMode.light`, сплэш без чёрной вспышки) — смена системной темы его не меняет.
- ☐ Бейджи типов: идиома — янтарь, фразовый глагол — teal, слово — зелёный green 800 (до этапа 10 — индиго; одинаково в обеих темах).

## 5. Уведомления

- ☐ ~09:00 приходит уведомление с локализованным заголовком («Word of Day — …» / «Слово дня — …» / «Kata Hari Ini — …» — по языку устройства); контент = слово дня ДНЯ срабатывания.
- ☐ Тап по уведомлению → карточка этого же дня (холодный и тёплый старт — проверить хотя бы один из них).
- ☐ (Android 13+, если появится устройство) отказ в `POST_NOTIFICATIONS` не ломает виджет; после отказов ОС скрывает диалог — включать в настройках.
- ☐ Канал с локализованным именем («Word of Day» / «Слово дня» / «Kata Hari Ini») появился в настройках приложения (создаётся лениво при первом показе — v22 плагина, это норма; смена языка устройства подхватывается при следующем запуске — Android разрешает переименование канала).
- ☐ Описание канала в настройках ОС — на языке устройства, время в локальном формате: «Daily word notification at 9:00 AM» / «Ежедневное уведомление со словом дня в 9:00» / «Pemberitahuan kata harian pada pukul 09.00».

## 7. Релизный APK

- ☑ `flutter build apk --release` собирается (подпись debug-ключом, `signingConfig debug` в `app/build.gradle.kts`).
- ☑ `aapt dump permissions` релизного APK: `INTERNET` нет (в debug есть — оверлей Flutter, норма); `ACCESS_NETWORK_STATE`/`WAKE_LOCK`/`FOREGROUND_SERVICE` — из androidx.work:work-runtime 2.11.2 (транзитивно androidx.glance 1.2.0 в home_widget 0.10.0), сетевого доступа не дают; источник подтверждён blame-отчётом manifest merger.
- ☑ `adb install --user 0 -r app-release.apk` поверх debug-версии (подписи совпадают) — выполнено 28.09.2026 на RMX2001: `Success`, запуск `am start .MainActivity` без FATAL/ANR в logcat, процесс жив (`pidof`), кадры рендерятся (SurfaceFlinger); после переустановки лаунчер сам прислал `APPWIDGET_UPDATE` в `WordWidgetProvider` (виджет перерисуется).
- ☐ Ручной smoke на устройстве: виджет на домашнем экране → тап → карточка слова дня (+ белая «W.» в шторке, если пришло уведомление).

## 8. Произношение слова дня (этап 9)

- ☐ Кнопка-динамик справа от слова: тап → слово/фраза дня озвучена системным TTS-движком (en-US); во время речи иконка меняется на «стоп».
- ☐ Повторный тап во время речи — воспроизведение останавливается.
- ☐ Уход приложения в фон во время речи — звук останавливается сам (WidgetsBindingObserver в `HomeScreen`).
- ☐ Тап по виджету на другое слово во время речи — старое слово замолкает.
- ☐ Идиома/фразовый глагол озвучиваются целиком (вся фраза — это и есть «произношение записи»).
- ☑ Нет TTS-движка или голоса en-US — кнопки в карточке нет, всё остальное работает (мягкая деградация; покрыто `pronunciation_service_test.dart`).
- ☑ Новых прав в релизном APK нет, `INTERNET` отсутствует — `aapt dump permissions` после сборки этапа 9.

## 9. Локализация и редизайн (этап 10)

- ☐ Язык устройства en → UI на английском; ru → на русском; id (включая legacy-код «in») → на индонезийском; неподержанный язык → английский (фолбэк).
- ☐ Лончер-лейбл и имя в переключателе задач — «Word of Day» во всех локалях (бренд не переводится).
- ☐ Дата в карточке локализована: «27 September 2026» (en/id) / «27 сентября 2026» (ru).
- ☐ Виджет в пикере лончера: имя «Word of Day» (en) / «Слово дня» (ru) / «Kata Hari Ini» (id); описание — на языке устройства (`values-ru` / `values-id`).
- ☐ Тёмная системная тема: приложение и сплэш остаются светлыми (нет чёрной вспышки), виджет на домашнем экране — тёмно-зелёный.
- ☐ Пикер виджетов: перевод в превью-карточке остаётся русским до локализации словаря (schema v2) — задокументированное ограничение этапа 10.
- ☑ Все строки UI и уведомлений — в ARB (`lib/l10n/`), захардкоженных нет; тесты проверяют en-ожидания (локаль тестового окружения).

## 10. iOS (этап 11) — на Mac (Windows не собирает iOS)

Автоматизировано на Windows ☑: `flutter analyze` чисто, `flutter test` 76/76 (iOS-ветки — через `ThemeData(platform: TargetPlatform.iOS)`), SPM-резолв плагинов успешен (`flutter pub get` без ошибок, все 4 плагина в `GeneratedPluginRegistrant`). Ниже — ручная приёмка при доступе к macOS + Xcode.

- ☐ `flutter run` на iPhone/iPad (iOS 15+) или симуляторе: карточка слова дня, зелёная светлая тема, локализованная дата.
- ☐ Навбар — CupertinoNavigationBar (не Material AppBar); кнопка-динамик — Cupertino с SF-иконкой (volume_up ↔ stop_fill); индикатор загрузки — CupertinoActivityIndicator.
- ☐ Первый запуск: системный диалог разрешений уведомлений показывается ОДИН раз (alert + sound); «Разрешить» → уведомление приходит ~в 09:00 локального времени (баннер + звук, без бейджа); тап → карточка того же дня.
- ☐ Отказ в разрешении: приложение и карточка работают; повторный диалог не появляется (мягкая деградация, как на Android).
- ☐ Перезагрузка iPhone: расписание уведомления сохранилось (iOS хранит его сама — boot-ресивер не нужен).
- ☐ Имя под иконкой и в переключателе задач: en — «Word of Day», ru — «Слово дня», id — «Kata Hari Ini» (симуляторы с разными языками).

- ☐ TTS: кнопка-динамик озвучивает слово en-US (AVSpeechSynthesizer); повторный тап/уход в фон — стоп.

## 11. Фото-ассоциация к слову дня (этап 12)

- ☐ Карточка без фото — кнопка «Добавить фото-ассоциацию» (локализована); тап → платформенный выбор источника: Android — bottom sheet «Камера / Галерея», iOS — action sheet с Cancel.
- ☐ Съёмка камерой (Android): системная камера открывается БЕЗ диалога разрешений (право `CAMERA` в манифесте отсутствует — интент); снимок появляется в карточке (16:10, скругление).
- ☐ Выбор из галереи: системный Photo Picker (Android 13+) / галерея; выбранное фото в карточке.
- ☐ Фото сохраняется между запусками приложения и переживает перезагрузку устройства (documents/word_images).
- ☐ Ассоциация привязана к слову, а не дате: слово того же id в другой день (годовой повтор формулой §5) показывает ту же картинку.
- ☐ «Заменить фото» — новый выбор перезаписывает старый (один файл на запись); «Убрать фото» — секция исчезает, возвращается кнопка добавления.
- ☐ Отмена на любом шаге (тап мимо шита / Cancel / выход из камеры без снимка) — карточка без изменений, без ошибок.
- ☐ На виджете и в уведомлении фото не появляется (только текстовый контракт §6).
- ☑ Сбой плагина/хранилища — тихая деградация (карточка работает), покрыто `word_image_service_test.dart`.
- ☑ Релизный APK (48.3 МБ, 01.10.2026): `aapt dump permissions` — НОВЫХ прав нет (`CAMERA` и `INTERNET` отсутствуют; состав как на этапе 9: boot + POST_NOTIFICATIONS + VIBRATE/WAKE_LOCK/ACCESS_NETWORK_STATE/FOREGROUND_SERVICE от плагинов).
- ☐ (iOS, на Mac) системные диалоги камеры/фото показываются один раз с локализованными текстами; отказ — фото недоступно, приложение работает (риск §9-16).
