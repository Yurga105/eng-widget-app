# Бизнес-идеи — процесс ведения бэклога

> `docs/ideas/` — инбокс бизнес-идей по развитию «Word of Day».
> Сами идеи живут в [`BACKLOG.md`](BACKLOG.md); этот файл — правила, по которым идея туда попадает и превращается в этап разработки.
> Заведено 02.10.2026, после завершения v1.0 (этапы 0–12): источник новых этапов (13+, v1.1) — бэклог идей (PLAN.md §8).

## 1. Принципы

- **Низкое трение**: мысль пришла → сразу карточка в `BACKLOG.md` со статусом 💡. Сырая формулировка — нормально; главное — контекст, чтобы через месяц было понятно, что имелось в виду.
- **Идеи не удаляются**: отклонённые остаются со статусом ❌ и причиной — это копит историю решений и защищает от повторного обсуждения.
- **Честность к ограничениям**: PLAN.md §1 фиксирует офлайн/без сети/без подписок. Идея, ломающая ограничение, НЕ отбрасывается — в карточке честно помечается конфликт, решение принимает владелец продукта.
- **Одна идея — один ID**: `B-###`, номера не переиспользуются.

## 2. Категории

| Категория | Про что |
|---|---|
| `монетизация` | доход: платные функции, пакеты, донаты (следить за конфликтом §1) |
| `рост` | привлечение новых пользователей: ASO, шеринг, рефералы, витрины виджетов |
| `удержание` | возвращаемость: нотификации, стрики, коллекции, привычка |
| `контент` | словарь и данные: новые типы записей, уровни, языки, объём базы |
| `партнёрства` | интеграции и коллаборации: школы, блогеры, издательства |
| `продукт` | качество ядра: UX, платформы, виджеты, производительность |

Список открыт: новая категория добавляется сюда и в сводную таблицу `BACKLOG.md`.

## 3. Статусы

```text
💡 новая → 🔍 исследуется → 📋 принята (этап N в PLAN.md) → ✅ реализована
                └────────────────────────────────→ ❌ отклонена (причина)
```

| Статус | Значение |
|---|---|
| 💡 новая | сырая запись, ещё не оценивалась |
| 🔍 исследуется | идёт проработка: оценка эффекта/затрат, проверка конфликтов |
| 📋 принята | решение делать: карточка получила номер этапа в PLAN.md §8 |
| ✅ реализована | этап выполнен (дата и номер этапа в карточке) |
| ❌ отклонена | не делаем; причина обязательна |

## 4. Шаблон карточки

```markdown
### B-###: Короткое название

- **Дата:** ГГГГ-ММ-ДД · **Категория:** … · **Статус:** 💡 новая · **Эффект:** низк/средн/высок · **Затраты:** низк/средн/высок
- **Конфликт с PLAN.md §1:** нет / ДА (какой именно) — требуется решение владельца
- **Проблема / возможность:** что болит или чего не используем (1–2 предложения)
- **Суть:** что предлагаем сделать (1–3 предложения)
- **Ожидаемый эффект:** метрика и направление (например: «установки, +N% за счёт шеринга»)
- **Заметки / открытые вопросы:** всё остальное; ссылка на проработку, если есть
```

Правило заполнения: **сначала строка в сводную таблицу, потом карточка** — таблица всегда даёт полный обзор без скролла по файлу.

## 5. Путь идеи до кода

1. **Запись** — карточка в `BACKLOG.md`, статус 💡.
2. **Триаж** (периодический): оценка эффекта/затрат, проверка конфликта с PLAN.md §1 → статус 🔍 либо сразу ❌ с причиной.
3. **Принятие** — статус 📋; в таблицу этапов PLAN.md §8 добавляется строка «Этап N» со ссылкой на карточку; критерий приёмки — из поля «Ожидаемый эффект».
4. **Реализация** — по DoD PLAN.md §10; после закрытия этапа карточка получает ✅ и дату.

## 6. Путь роста

Если идее нужна глубокая проработка (рынок, конкуренты, расчёт юнит-экономики) — заводится файл `docs/ideas/research/B-###-slug.md`, ссылка кладётся в поле «Заметки» карточки. Пока таких файлов нет — каталог не создаём, заведём с первой проработкой.
